# 聊天、会话与待办完善（2026-10-18）

本轮完成聊天输入、会话管理、统一待办及恢复稳定性四项开发。按使用者要求，先做源码、构建和本机自动化，新增功能的模拟器/真机交互统一留待最后验收。本轮没有连接云实例、修改服务器或发起模型调用。

## 使用入口

- 对话中长按用户消息可复制整条消息；回复下方可复制完整回复；每个代码块右上方可复制代码。剪贴板使用鸿蒙原生纯文本接口。
- 输入框使用原生多行自适应布局，显示 1 至 6 行，最高 164vp、最多 20000 字符。页面启用 RESIZE 键盘避让；横竖屏和软键盘实际表现仍待统一验收。
- 草稿、未确认发送的消息 ID，以及未提交 Question 字段在本次应用运行期间按服务器、目录、会话隔离暂存；切换会话和服务器后可以恢复。退出应用不保留草稿，不增加本地聊天历史数据库。最多暂存 100 个对话，达到上限时拒绝丢弃旧草稿并提示先清理。
- 历史列表提供名称搜索、服务器搜索、刷新、分页、最近/本机归档切换。会话右侧管理按钮支持服务端改名、本机置顶和本机归档。旧书签可在重开应用后显示，移回最近后立即可见。
- 置顶/归档仅保存列表设置及书签标题/目录，不删除服务器历史、不停止任务。实际 V2.0.29 的 PATCH 接口用于改名；没有伪造归档 endpoint 或覆盖未知服务端 metadata。
- 更多功能或侧栏中的“待办中心”列出当前连接服务器所有已知项目的问题与审批，可按问题/审批筛选，点击打开其实际工作目录和会话。问题仍在会话内填写，审批仍在会话内预览、重新读取并单次批准或拒绝。
- 侧栏显示运行中、等待回答、等待审批及读取失败后的待确认状态。归档不会屏蔽待办。待办中心覆盖当前服务器，切换服务器后重新同步，不承诺同时维持多个服务器连接。

## 恢复与边界

发送回执丢失后，切换会话仍保留原始消息 ID；服务器历史确认收到后清除待重试状态。未知发送结果重试保持同一 ID，明确拒绝的请求恢复可编辑输入。停止按钮有进行中状态，重复触摸只提交一次中断。

每次重建 SSE 使用新的流序号，旧流的文本和失败回调不会修改当前流；认证或证书校验失败后停止自动读取，提供手动重新连接。退后台取消待办快照的发布资格，回前台建立新流并同步。原生状态快照可恢复启动前已经运行的其他会话。

会话以每页 50 条读取，当前列表最多 500 条，可用服务器名称搜索继续查找。待办覆盖当前目录、已知项目及仍有旧待办的目录，最多 64 个目录，分批最多 6 个待办请求并发；最多显示 500 项。达到边界明确提示；某个目录或类型读取失败时保留对应旧项并标为待确认，成功读到空结果才清除旧项。待办中心不直接批准，也不批量批准。

消息窗口保留原有 300 条上限。消息归并改为线性去重，未改变的轮询保留数组及消息对象引用；无变化不重复构建聊天内容，自动滚动回调合并。Diff/文件预览继续有界，较长 Markdown 明确显示截断提示，完整正文可复制。

## 自动化结果

- 核心逻辑 26 项、协议/状态 78 项、审批元数据 6 项、外观 3 项、存储/剪贴板 5 项、本机 HTTP 集成 6 项、域名候选生成器 2 项，共 126 项通过。
- 完整 ArkTS 编译、打包和本机调试签名通过，无 ArkTS 错误或警告。最低 API24、编译/目标 API26 保持不变。
- HTTP 集成使用测试进程内的 loopback 服务，真实 HTTP 覆盖超过 50 个会话的分页、全历史搜索、PATCH 改名、发送回执丢失后历史恢复、跨项目待办、审批预览重读及一次带目录范围的决策。没有调用云服务或 Agent。
- 4 项合成负载覆盖 50000 条消息归并、1000 页历史/300 条窗口、100000 行 Diff 预览及大 Markdown。测量输出位于忽略的 .test/performance.json，属于 Node 逻辑测量，不代表设备帧率。

# 鸿蒙原生比例与模型浮层（2026-10-21，第二轮）

> 2026-10-22：当前模型浮层与验收入口以 [MODEL-PREFERENCES.md](MODEL-PREFERENCES.md) 为准；下文保留当时实现和验收记录。

本轮接续 [此前的界面调整](LUMINOUS-UI.md)，按使用者的新截图收敛过大的侧栏、字号与卡片比例，并把模型高频选择恢复为顶部轻量浮层。

## 参考依据与实现选择

查阅了 [HarmonyOS 官方设计总览](https://developer.huawei.com/consumer/cn/design/)、[设计入门](https://developer.huawei.com/consumer/cn/design/devstart/)、[HarmonyOS 7 官方介绍](https://consumer.huawei.com/cn/harmonyos-7/)和[华为音乐官网](https://consumer.huawei.com/cn/mobileservices/music/)。官方资料强调空间层次、系统材质、交互响应和多设备适配。本轮还实际打开 API26 模拟器内的华为日历，观察月视图、系统标题栏、分段控件与空态；没有新增或修改日程。

以下配色与尺寸是针对本客户端的实施选择，不把它们表述为华为强制规范。华为音乐官网大图和部分深入设计页面请求超时，因此没有声称逐屏核对当前音乐 App。

- 中性灰白、清晰正文、白色分组容器；深色对应中性黑灰。蓝色主要用于选中态和主操作，绿色继续表达成功状态。
- 原生 Navigation、SideBarContainer、SegmentButton、bindPopup 与系统选择器保持各自职责；API26 沿用模块已有的 UIMaterial 沉浸光感设置，内容区保持可读。
- 主内容区以 15vp 正文、14vp 控件文字、12–13vp 辅助信息为基准；管理页标题约 20–22vp。系统字体缩放继续生效，没有修改设备全局字号。
- 手机侧栏宽度上限 276vp，并按窗口的约 74% 计算；宽屏嵌入栏为 256vp。历史名称 14vp、历史行最低 44vp，工作区入口最低 40vp。分段按钮单独调整内边距，避免窄栏的“本机归档”被截断。
- 更多功能改用每组一个容器，组内细分隔线，移除重复的大标题；缩小图标和辅助说明，保留清晰的主次关系。
- 空态缩小标记和标题，移除大面积色晕与轨道装饰。聊天正文、思考、工具和输入区继续保留之前的紧凑间距。

## 模型操作

顶部模型按钮使用原生 `bindPopup` 锚定在按钮下方。浮层宽度最高 300vp，展示最多三个快捷候选、实际提供商与输入能力，当前模型以勾选标识。关闭浮层后仍留在当前对话。

候选只从服务器真实目录选取，优先保留当前模型、MiMo 与 DeepSeek 的现有入口，其余由目录补齐；不生成不存在的模型。相同显示名称保留各自完整 ID，切换始终提交准确的提供商和模型身份。

“全部模型”进入原有的完整搜索与分页页面，适合较大目录；“模型与接入”进入管理页。没有加入服务端尚未提供的思考等级或对话长度开关。

浮层点空白或系统返回关闭；选择当前项不重复提交。切换时禁用重复操作，失败留在浮层内给出错误与重试入口。打开管理页、切换会话/服务器、接收通知跳转或应用退到后台时关闭临时浮层。列表不获取独立输入焦点，避免关闭后再次打开被旧焦点状态打断。

深色实测发现系统材质过度透出正文，已为内容区补充实底。系统仍负责浮层的定位、遮罩、圆角与阴影。

## 原创图标素材

使用内置 `image_gen` 生成一个蓝色玻璃代码标记，采用真实透明 PNG 原图直接入库，未裁切、改色或覆盖原模板素材。尺寸 1254×1254，RGBA；已检查 Alpha 范围为 0–255。

- 全局前景：`AppScope/resources/base/media/opencode_mark_v1.png`。
- entry 副本：`entry/src/main/resources/base/media/opencode_mark_v1.png`。
- 对应 `opencode_launcher_v1.json` 配置独立的 `opencode_background_v1.svg` 中性背景；应用与 EntryAbility 指向新版分层图标。
- `CodeMark` 在欢迎页和侧栏复用同一资源；导航、工具和列表操作继续使用系统符号。

完整生成提示词保存在 [ICON-PROMPT.md](ICON-PROMPT.md)。素材只负责品牌识别，没有用图片替代交互控件。

## 验证与范围

- 完整 ArkTS 编译、打包、原有调试签名与 API26 模拟器安装启动通过。
- 265 项 Node 与 2 项 Python 回归通过，包含新增快捷目录身份/缺失项/去重检查、深浅主题对比度及 42 项提醒检查。
- 原生快捷浮层：锚点与尺寸、点空白关闭、系统返回、当前项零 POST、拒绝后重试、精确 ID 请求及完整搜索入口均通过。侧栏实际宽度检查要求不超过手机窗口的 76%。
- 原生完整目录：77 个模型的分页、按渠道/ID 搜索、精确切换、失败重试、当前项零 POST、无结果搜索及管理页返回均通过。
- 原生导航：模型、Agent、上下文、分叉、导出、工具详情与父页面返回通过；思考完成自动折叠、打开详情期间的工具结果更新和深浅主题切换通过。
- 布局实测：折叠思考到正文 8vp、工具到下一段思考 14vp；空输入区 42vp，多行输入增加到 86vp，发送按钮保持底部对齐，测试后清空草稿。模拟器未提供可见软键盘窗口，因此没有把这项几何检查记为通过。
- 原生浮层使用 160ms 淡入；自动化等待入场完成和控件启用后再点击，避免把动画期间的连续注入误认为稳定交互失败。截图与详细日志保存在本机 `.test/harmony-*`，不作为生产素材入库。

本轮原生流程使用仅监听 loopback 的测试服务器，未调用真实模型或保存真实模型 Key。图标生成只发送上面的设计描述。API24 真机、Pad 横屏/分屏、软键盘遮挡及极端系统字体仍需后续设备验收。

```powershell
node tests/model-controls-ui.mjs

```

同一设备的 UI 脚本顺序执行。验收后移除本轮测试配置与端口映射、停止本轮 fixture 进程，保留原服务器配置和签名资料。

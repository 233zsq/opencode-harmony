# 移动体验与通知审查（2026-10-20）

对比基线 `8e7dac3` 与实现 `bf0fef8`，按前一轮给 DeepSeek 的需求审查。工作分支为 `feat/mobile-usability-notifications`；修复保留原生 ArkTS/ArkUI、API24 兼容及 API26 材质方向。

## Standards

发现 3 项，均修复：

1. **P1，提醒设置持久化。** 权限刷新与初始化并发会把保存的关闭开关覆盖为默认开启。设置加载使用单次 Promise，未完成时不写；权限刷新与开关持久化分离，即便读取失败也不回写默认开关，显式切换只保存用户修改的组。
2. **P1，通知导航迟到响应。** 旧服务器会话读取完成后可污染新连接。每次异步返回都核对 API/服务器/导航代次；连接还返回成功操作的归属代次，用户在连接恢复中主动切换会话后，旧通知导航停止。
3. **P2，权限拒绝后的双弹窗。** 首次拒绝授权后立即再打开设置页。现在拒绝即结束本次操作，只有下一次明确点击才打开系统设置；按钮文案与动作保持一致。

## Spec

发现 5 项，均修复：

1. **P1，安全定位。** 与 Standards 第 2 项重合；新增覆盖会话读取和真实 connect 恢复两个等待阶段的竞争测试。
2. **P1，运行中会话完成漏报。** 历史基线不再预先登记 streaming 助手消息的完成键。
3. **P2，断线历史误报。** SSE 传输错误、重连和后台返回都建立静默补同步基线；部分读取失败不提前解除抑制。
4. **P2，管理页提示不可见。** 只有前台实际可见的聊天使用安静提示；设置/审查/项目页、覆盖式抽屉和 Sheet 改用系统提醒，宽屏并排侧栏保持聊天可见。关闭的提醒类型同时关闭其安静提示。
5. **P2，其他会话失败被报成功。** 从运行列表消失仅作为候选，读回真实 outcome/助手终态再分类，并采用真实目录和一致的消息身份去重；无法确认的结果不称为成功。

两轴共 3 / 5 项，重合 1 项。各轴最高均为 P1：Standards 为设置覆盖及迟到导航，Spec 为运行任务漏报及迟到导航；均有对应修复与回归。

# 界面层级与阅读体验更新（2026-10-21）

> 2026-10-22：当前模型浮层与验收入口以 [MODEL-PREFERENCES.md](MODEL-PREFERENCES.md) 为准；下文保留当时实现和验收记录。

本轮针对手机截图中的三个问题：字号偏小、所有选择器堆在底部、管理功能缺少层次。使用原生 ArkTS / ArkUI 在 `feat/luminous-ui` 实现，没有新增业务依赖。

## 页面安排

| 入口 | 当前展示 | 返回位置 |
| --- | --- | --- |
| 顶部模型 | 完整模型选择页，搜索、列表和底部操作分开 | 当前对话 |
| 会话 Agent | 完整 Agent 选择页，说明与切换状态可阅读 | 当前对话 |
| 更多功能 | 当前对话、工作空间、应用设置三组卡片 | 当前对话 |
| 用量、分叉、导出 | 各自独立的原生页面 | 打开它的功能页或当前对话 |
| 工具摘要 | 完整详情页，参数与执行结果独立显示 | 当前对话 |
| 模型与接入 | 先浏览或搜索提供商，再进入对应认证页 | 认证页先回提供商列表 |
| 服务器连接 | 已保存的连接优先展示，按“添加服务器”展开表单 | 当前对话 |
| 会话短操作、附件预览 | 保留原生半模态，确认操作使用系统对话框 | 原页面 |

Navigation / NavDestination 继续提供系统标题与返回按钮。替换目的页采用原子 `replacePath`，避免清空路由再推入时，中间的空栈被当成用户返回。模型、Agent 和工具详情随连接或会话作用域变化关闭；导出返回时取消未完成的读取，迟到结果不会再打开保存器。

## 视觉与尺寸

- 暖白背景、青绿色强调、深色对应的柔和薄荷强调；主次文字、代码、警告和 Diff 使用独立语义颜色。
- 欢迎页与侧栏共享静态代码标记；空态使用轻柔的色晕与轨道描边。没有新增持续动画或着色器循环。
- 模型与 Agent 名称 17vp、主要操作与聊天正文约 16vp、说明 14–15vp、技术 ID 12vp。系统字体缩放规则保留。
- 选择列表改为分隔明确的卡片，搜索框至少 48vp，主要操作至少 44–48vp。长名称允许两行，完整 ID 可按需阅读。
- 侧栏放大历史会话与工作区入口；欢迎页只呈现最近三个会话标题，移除重复的服务器和模型信息块。
- 输入区减轻阴影和描边，空输入保持原有 42vp，发送按钮 44vp，多行输入仍与按钮底部对齐。
- 认证表单从顶部排列，避免短内容垂直居中造成大块空白；工具详情放大按钮，代码行高增加至 22vp。
- 思考仍在结束后自动收起；工具仍以摘要展示，不自动展开。没有为了增大字号恢复整块固定高度或额外工具空行。

通用材质仍使用 API24 已有属性；API26 原生控件沿用 UIMaterial 沉浸光感配置。未新增静态依赖 API26 的模块或资源填充重载。最低兼容 API24、目标与编译 API26 保持原设置。

## 已验证

- 完整 ArkTS 编译、打包、调试签名、API26 模拟器安装启动成功。
- 263 项 Node 回归与 2 项 Python 域名校验通过；其中包含 94 项协议/状态、42 项提醒和深浅主题的阅读对比度检查。
- 原生模型流程：77 项分页、名称/渠道/ID 搜索、精确 ID 切换、拒绝后重试、当前选项不重复提交、空结果与配置入口。
- 原生提供商流程：DeepSeek 填写未保存的测试 Key 后返回、搜索 Xiaomi、对应认证表单一致、旧 Key 清空、仅一次向本机 Xiaomi 接口保存合成凭据。
- 原生页面流程：模型、Agent、用量、分叉、导出与工具均有系统返回；功能子页回功能页；思考结束收起，工具结果实时更新；侧栏与深浅主题切换通过。外观测试结束恢复原设置。
- 原生 Agent：名称与搜索、隐藏项过滤、精确切换与模型读回、拒绝、丢失回执后只核对不重发、运行中禁用均通过。
- 原生导出：读取失败和取消、系统保存器取消、360 条历史的 TXT 与 Markdown 保存后重新导入核对；合成推理内容和附件字节不进入导出，工具详情只在主动勾选后包含。返回路径已随新页面同步验证，测试草稿清空。
- 原生几何测量：折叠思考到正文 8vp，工具到下一段思考 14vp，空输入 42vp；三行输入展开为 86vp，发送按钮保持底部对齐。模拟器本轮未暴露可见软键盘窗口，键盘遮挡几何明确跳过。
- 4 项 Node 合成负载检查通过；其耗时不代表模拟器或设备帧率。

本轮设备范围是 API26 模拟器。API24 真机、Pad 横屏/分屏、系统大字体极端设置与 API26 真机材质性能留待后续验收，不能沿用旧版本的设备结论。Node 逻辑和对比度检查也不代表设备帧率。

原生自动化使用仅监听 loopback 的 `tests/fake-server.mjs`；未发送真实模型提示、未写入真实提供商凭据、未改动云服务器项目。截图与详细日志保存在被忽略的 `.test/luminous-*` 中。

## 复现入口

先启动本机 fixture，使用 HDC 反向映射，并在应用中明确选择测试连接和 `ses_fixture`。脚本检查“本机测试模型”标签后才进行切换或凭据操作；测试 Key 均为合成值。

```powershell
$env:OPENCODE_FIXTURE_PORT='55261'
node tests/model-controls-ui.mjs
node tests/provider-ui.mjs
# 从认证页返回当前对话后：
node tests/luminous-ui.mjs
node tests/agent-export-ui.mjs
node tests/chat-layout.mjs
node tests/composer-smoke.mjs
```

各 UI 脚本顺序执行，不同时控制同一模拟器。界面流程入口已同步更新；`REQUIRE_CHAT_CARDS=1` 要求相邻工具、思考与正文测量都存在。验收后移除本轮创建的测试连接、端口映射和 fixture 进程，保留用户原有配置。

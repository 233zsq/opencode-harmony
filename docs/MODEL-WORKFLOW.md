# 模型配置与选择完善（2026-10-19）

## 本轮结果

修复提供商选择与配置表单身份不一致；保存操作固定使用点击时的内容。聊天顶部改为可搜索的原生模型面板，保持 API24 最低兼容、API26 编译和目标版本。

本轮使用 API26 模拟器、本机 loopback 服务及合成 Key 验收。没有向真实提供商保存凭据、发起模型调用或修改云服务器配置。最新 API24 / API26 真机检查仍按使用者安排延后。

## 提供商表单错位

原包可复现：重新打开测试项目以清空提供商表单状态，选择 DeepSeek，搜索 Xiao，再点击 Xiaomi；列表已经选择 Xiaomi，下方标题仍为 DeepSeek。只需选择和搜索，不需要输入 Key。若沿用上一轮已打开的表单，旧标题可能刚好与下一次选择相同，因此验收必须固定初始状态。

使用本机假 Key 核对原包回执，实际提交地址为 Xiaomi，显示仍是 DeepSeek。结论来自受控测试，不推断使用者真实账号是否曾提交过凭据。

原表单通过 current() 间接读取选择，缺少提供商身份对应的重建边界，旧标题、认证方式和回调可被复用。现在以明确的 selected 与 entries 构建表单，并以提供商 ID、名称、账号和认证方式元数据确定身份；标题、认证方法、账号都来自同一个集成快照。切换后清除旧 Key 和认证表单，保存按钮附近显示目标提供商。

保存前的异步空闲检查期间，原包会读取后来编辑的 Key 和账号名称。现在请求地址、Key、名称、认证方式和答案在点击时确定；保存期间禁用相关输入。断网或回执未确认仍先刷新账号列表，不自动重复保存。

## 手机使用

- 新增接入：右上角更多功能 → 模型与接入 → 提供商或兼容渠道。保存后模型目录来自当前服务器，真实可用性仍需使用自己的 Key 进行一次实际聊天确认。
- 切换模型：点击聊天顶部模型名称，输入名称、渠道或模型 ID。多个关键词共同匹配，名称相同时可通过完整 ID 区分。
- 目录先显示 40 个，点击显示更多再增加 40 个；搜索覆盖完整目录，空搜索把当前模型放在最前。重复模型 ID 去重，服务器原目录顺序保持不变。
- 每项显示完整渠道/模型 ID 和服务器声明的图片/PDF能力。能力声明用于附件检查，不代表第三方真实调用已经验证。
- 成功切换后关闭面板；失败保留搜索结果与错误，可手动重试。点击当前模型直接返回，未重复请求切换。面板底部可直接进入模型与接入。
